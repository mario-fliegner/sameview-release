Google Play Data Safety
========================

Last updated
2026-10

==================================================
APP OVERVIEW
==================================================

In normal use, SameView works locally and offline on the user's device.

The app:
- does not require a user account
- has no backend or cloud synchronization
- contains no analytics SDKs
- contains no advertising SDKs
- contains no crash reporting SDKs
- stores user data locally on the user's device
- declares the INTERNET permission solely for the optional DeinWackelbild order

The only case in which the app itself transmits user data off the device is the
optional DeinWackelbild order, and only after the user explicitly starts it
(see OPTIONAL DEINWACKELBILD ORDER).

==================================================
DEFINITION USED IN THIS DOCUMENT
==================================================

This document follows the Google Play Data safety definitions:

- "Collect" means transmitting data from the app off a user's device.
- User data that is only processed locally on the user's device and not sent
  off device does not need to be disclosed.

Earlier revisions of this document (2026-07) listed on-device data as
"Collected: Yes". That did not match the Google definition and did not match
the v1.0 submission record (05_Releases/2026-07-24_PlayStoreSubmission.docx:
no data types selected). On-device data is now listed separately below.

==================================================
DATA SHARING
==================================================

SameView does not transmit user data to developer servers.

User data only leaves the device when the user explicitly initiates one of:
- an export or the Android Share Sheet
- the optional DeinWackelbild order

Photos - Shared: No

Basis: Google Play guidance does not require a transfer to a third party to be
disclosed as "sharing" when it is "based on a specific user-initiated action,
where the user reasonably expects the data to be shared". The DeinWackelbild
transfer starts only after an explicit user action, and immediately before the
transfer the app discloses that the two images go to DeinWackelbild.de and that
ordering is completed there.

This document does not rely on the "service provider" exception.

Open point: SameView receives a 10% commission on orders attributable to this
handoff. The official guidance consulted does not address a commercial
relationship in connection with this exception. This must be checked when the
live Play Console form is completed (see OPEN ITEMS). No conclusion is drawn
here.

==================================================
DATA SECURITY
==================================================

- Normal use causes no network traffic
- The only network transmission by the app is the optional DeinWackelbild order
- That transmission uses HTTPS
- No automatic upload and no background upload
- In normal use, user data remains on the device
- User sessions are excluded from Android Auto Backup and device transfer
- No automatic cloud synchronization

==================================================
PERMISSIONS
==================================================

Required
- CAMERA

Optional
- ACCESS_FINE_LOCATION
- ACCESS_COARSE_LOCATION
- ACCESS_MEDIA_LOCATION

Declared for the optional DeinWackelbild order
- INTERNET

Technical note
- The final release manifest contains the transitive permission ACCESS_NETWORK_STATE from AndroidX Media3.
  SameView-owned code does not use it, and it does not itself permit data transmission.
- android.permission.DUMP is not requested by SameView. It appears only as the
  android:permission protection attribute of the AndroidX ProfileInstallReceiver and
  grants no capability to the app.

==================================================
OPTIONAL DEINWACKELBILD ORDER
==================================================

What it is
- A separate optional feature to order a physical lenticular print (Wackelbild).
- Nothing is transferred through normal use of SameView.

When data is transferred
- Only after an explicit user action.
- Immediately before the transfer, the app discloses that the two images go to
  DeinWackelbild.de and that ordering is completed there.
- No automatic upload, no background upload.

What is transferred
- Exactly two prepared JPEGs: reference + capture.
- They are derived/prepared copies, not the stored originals.
- They contain no EXIF/GPS metadata.
- If the date option is enabled, the date text is rendered into the image pixels.
- Technical handoff values, including a partner identifier, format, orientation
  and direction.
- No SameView session ID and no external reference is sent.
- No analytics, telemetry or tracking data.

How
- HTTPS.
- The checkout/configurator then opens externally in a Chrome Custom Tab /
  browser. Data the user enters there is entered on the DeinWackelbild website,
  not in SameView.

Recipient / operator / seller
- O.Schulze / M.Monka GbR (DeinWackelbild), Wolfener Str. 32-34, 12681 Berlin, Germany
- The physical print order is completed with DeinWackelbild under its own terms
  and is separate from the SameView purchase on Google Play.
- SameView receives a 10% commission on orders attributable to this handoff.

Retention
- If no order is completed, DeinWackelbild retains the transferred images for
  24 hours and then deletes them.
- Retention for completed orders is not documented here.
- SameView does not receive the transferred images back.

Never record the partner identifier value in this repository.
